# Licensing, Chain of Custody, Authenticity and Legal-Risk Gate

Use this whenever providing sound effect links, recommending downloaded media, constructing assets from source libraries, or working on NGO, client, commercial, monetized social, education, government or broadcast projects.

## 1. Asset status taxonomy

`DISCOVERED` → source is indexed.
`ORIGINAL PAGE OPENED` → author/title/file description from original site verified.
`PREVIEW AUDITIONED` → actual audio preview/file listened to, if available.
`RIGHTS REVIEWED` → applicable source/license/plan terms inspected.
`CLEARED FOR THIS USE` → based on verified terms and known project facts, appears permitted. For legal uncertainty use `HOLD—REQUEST PERMISSION`, not assurance.
`INSTALLED/EDITED` → specific file actually downloaded/imported/edited using current tools.

These flags are independent: opening a page does not verify the sound quality, and a commercial catalog page does not establish that this user owns a covering subscription.

## 2. Rights checklist for every recommended real file

1. Original sound creator/owner identity, original source page and asset ID.
2. Exact asset title and permalink (prefer stable original URL).
3. Origin/provenance: which archive, vendor or person recorded it; location/recording date only if verified.
4. License **at asset level**, not merely platform reputation; version and evidence URL.
5. Intended uses: NGO/client/public distribution, commercial/monetized social, paid campaign, television, cross-border sharing, edits/derivatives, broadcasting, website and future reuse.
6. Subscription status/seat/channel/project registration: *user account facts*, not assumptions.
7. Attribution and required link/title/creator/license version, if applicable.
8. Restrictions: standalone redistribution, reuse in unrelated projects, content ID registration, use on templates/tools, transfer to client, AI/ML uses if relevant, competing reuploads.
9. Record access date, license certificate if provided, purchase receipt and file checksum/asset identifier if editing begins.
10. Mark `PASS`, `HOLD`, or `FAIL`; explain uncertainty precisely.

## 3. Creative Commons and public-domain caution

- **CC0:** broad reuse generally intended without mandatory attribution; verify source/provenance and separate rights where applicable. Giving credit is often good practice even if not required.
- **CC BY:** attribution usually required; preserve author, title, source link, license version and modification notes according to that version.
- **CC BY-NC:** not a safe default for NGO videos—nonprofit status does **not** automatically make a use noncommercial. Treat client, promotional or monetized distribution as `HOLD/FAIL` until qualified legal/licensor authorization.
- **CC BY-SA or others:** examine adaptation/share-alike and downstream obligations carefully; not every CC license grants the same rights.
- **Unlabeled, site-shared or public archive:** availability/downloadability is **not** permission.
- **Royalty-free:** typically a license without recurring per-use royalties under defined scope, *not* free of copyright or unlimited rights.
- **Editorial use only:** do not assume promotional campaigns/client advertising are authorized.

Freesound states that the file-level licenses vary, including CC0, CC BY and CC BY-NC: https://freesound.org/help/faq/ . A search-result snippet is insufficient; inspect the *specific* file.

## 4. Platform-specific examples requiring verification

These are **risk flags**, not blanket legal conclusions; read today's terms for the actual plan/item:

- **Artlist:** Social vs Pro vs Business differs, especially client work, paid promotional use, seats, publication windows and clearlisting. Relevant official help: https://help.artlist.io/hc/en-us/articles/29490991524253-Understanding-Artlist-s-license/ .
- **Envato Elements:** current terms include project-specific registration/one license per project for most items, with limits on standalone redistribution. Official help: https://help.elements.envato.com/hc/en-us/articles/360000621783-Correct-Usage-of-Items .
- **Sonniss GDC:** license version can depend on download date; current version info: https://sonniss.com/gdc-bundle-license/ . Restriction against AI/ML use may apply and is separate from normal media production.
- **BBC Sounds archive:** archives may allow certain personal/educational uses but not general commercial/public reuse without permission; inspect archive's official current usage wording.
- **Wildlife/user-recorded archives:** rights differ between contributors and may be CC BY-NC; never generalize archive-level access to each recording.
- **Pixabay / Mixkit / ZapSplat / others:** check the exact sound-effect content license and attribution tier in effect for the user.
- **Video/social platform clips:** not valid sources of reusable SFX rights merely because video can be played or downloaded.

An asset from a paid pack cannot be rehosted in a client deliverable as a naked WAV simply because the final video using it was authorized; deliver embedded mix/stems only within the specific license scope.

## 5. Authenticity and factual media

**Documentary audio is a claim.** Natural footsteps could be Foley; a siren implies an incident; a particular spoken announcement implies place/time/language. When the cut implies source audio was recorded on location, be especially careful with replacement audio and add documentary/reconstruction disclosure as appropriate.

Examples:
- A generic air-conditioned room bed as stylized underscoring can be defensible; don't label it “actual Cambodia scam compound audio.”
- A Kathmandu airport clip may be authentic only when original recording metadata supports it. Never claim locality from background accents.
- Never edit a victim quote so its meaning changes. Separate reenactments from recorded interviews.
- No fabricated danger sounds to imply crimes that are not demonstrated.

## 6. Manifest format

| Asset ID | Cue ID | Origin URL | Creator | License/URL | User plan/permission | Date | File hash (if used) | Credit | Status |
|---|---|---|---|---|---|---|---|---|---|
| known file only | linked event | original | verified | exact | verified/unknown | checked | only if computed | exact required | PASS/HOLD/FAIL |

If source ownership, plan or license is unknown, write `unknown` rather than inventing a plausible label. Prefer a substitute with clear permissions over a perfect but legally risky effect. This guide is production risk management, not legal advice.
